# Связь

Android-клиент для [p2p-messenger-over-http](https://github.com/SolverNA/p2p-messenger-over-http) — терминального P2P-мессенджера на Go/libp2p.

«Связь» переносит тот же сетевой протокол на телефон: сообщения идут напрямую между устройствами, без центрального сервера, аккаунтов, облачной истории и push-уведомлений. Ключи, подписи и формат профиля совместимы с десктопным клиентом, поэтому Android-устройство и компьютер могут переписываться в одной сети.

> **Статус:** ранняя версия 0.1. Общий список публичных узлов upstream пока пуст, поэтому для связи обычно нужен хотя бы один запущенный bootstrap-узел.

## Возможности

- **Личные беседы 1:1** с историей, непрочитанными и локальными именами контактов.
- **Сквозное шифрование** транспортного уровня libp2p (Noise) и подпись каждого сообщения ключом Ed25519.
- **Доставка с подтверждением.** Исходящее сообщение остаётся в очереди на отправителе, пока получатель не сохранит его и не вернёт ACK. Повторы идут с нарастающей паузой (5, 10, 20, 40, затем до 60 секунд), порядок сообщений одному получателю сохраняется.
- **Статусы в реальном времени:** поиск собеседника, подключение, отправка, недоступность, причина сбоя и время до следующей попытки.
- **QR-коды:** показать свой Peer ID, отсканировать чужой, скопировать или отправить через системное «Поделиться».
- **Работа в фоне:** foreground-сервис с уведомлением о состоянии узла, автозапуск после перезагрузки, запрос исключения из оптимизации батареи.
- **Приватные уведомления:** на экране блокировки показывается только факт нового сообщения, без текста.
- **Настройки сети:** до 16 bootstrap-адресов, общий список узлов (авто, выключен или свой HTTPS-URL), экран состояния с адресами, соединениями, RTT и очередью.
- **Перенос профиля:** экспорт и импорт ZIP-архива с ключом и историей, совместимого с каталогом `--data` десктопной версии.
- **Два оформления:** Material You и One UI; режим «Авто» выбирает стиль по производителю устройства.

## Как это работает

```
Android «Связь» ───── WS/WSS ─────▶ bootstrap / relay ◀───── WS/WSS ───── десктоп
       └──────────── TCP/QUIC + Noise, напрямую или через DCUtR ────────────┘
```

1. При первом запуске создаётся постоянный ключ Ed25519; из него получается Peer ID.
2. Узел публикует подписанную запись о своих адресах ближайшим узлам каталога (bootstrap/relay).
3. Отправитель ищет запись получателя, подключается напрямую (TCP/QUIC, hole punching) или через реле и отправляет подписанный JSON.
4. Получатель проверяет подпись, сохраняет сообщение на диск и только затем подтверждает доставку.
5. Если получатель недоступен, сообщение ждёт в локальной очереди и повторяется при появлении сети.

Публичные узлы используются для обнаружения, установления связи и, если прямое соединение не удалось, ретрансляции. Шифрование при этом остаётся между конечными устройствами.

## Сборка

### Требования

- JDK 17 или новее;
- Android SDK с платформой 37;
- Android NDK `29.0.14206865`;
- Go 1.27.1 или новее;
- `gomobile` из `golang.org/x/mobile`.

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/29.0.14206865"
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export PATH="$(go env GOPATH)/bin:$PATH"

# Версия x/mobile берётся из gocore/go.mod
(cd gocore && go install golang.org/x/mobile/cmd/gomobile)
gomobile init
```

Пути можно не задавать, если `sdk.dir` уже прописан в `local.properties`, а NDK и JDK находятся в стандартных местах. `local.properties` в репозиторий не входит.

### Debug APK

```sh
./gradlew :app:assembleDebug
```

Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

Перед сборкой Gradle автоматически запускает `scripts/build-gocore.sh`: тот собирает Go-ядро в `app/libs/gocore.aar` через `gomobile bind` для ABI `arm64-v8a` и `x86_64`. Отдельно устанавливать AAR не нужно, и он не хранится в репозитории. Скрипт также выставляет выравнивание ELF-сегментов под 16 КБ страницы памяти.

### Release APK

```sh
./gradlew :app:assembleRelease
```

По умолчанию release подписывается debug-ключом, чтобы APK можно было установить вручную. Для распространения замените `signingConfig` в `app/build.gradle.kts` на собственный ключ.

### Проверки

```sh
./gradlew :app:testDebugUnitTest   # unit-тесты Kotlin
(cd gocore && go test ./...)      # тесты сетевого ядра
```

## Использование

1. Установите APK и запустите приложение.
2. На первом экране скопируйте свой Peer ID. При необходимости укажите адрес bootstrap-узла вида `/ip4/203.0.113.10/tcp/80/ws/p2p/12D3Koo...`.
3. Передайте свой Peer ID собеседнику — текстом или QR-кодом.
4. Откройте «Новая беседа», вставьте Peer ID или отсканируйте QR-код.
5. Оба устройства должны быть в сети. Если собеседник выключен, сообщение останется в очереди у отправителя.

Свой Peer ID, адреса, соединения, выбранные публичные узлы и состояние очереди видны в разделе «Сеть». Bootstrap-адреса и источник общего списка узлов настраиваются в «Настройках».

### Связь с десктопным клиентом

Запустите upstream-клиент в той же сети, например:

```sh
./messenger-tui --bootstrap /ip4/PUBLIC_IP/tcp/80/ws/p2p/PUBLIC_PEER_ID
```

Обменяйтесь Peer ID и добавьте собеседника в «Новой беседе». На Android достаточно указать тот же bootstrap-узел.

Профиль можно перенести в обе стороны через «Настройки → Профиль». ZIP-архив содержит `identity.key`, `state.json` и `sequence.json`; на десктопе его содержимое распаковывается в каталог `--data` при остановленном клиенте. **Архив не зашифрован** и содержит приватный ключ, поэтому обращайтесь с ним как с паролем.

## Ограничения

- Нет хранения сообщений на сервере: чтобы сообщение дошло, отправитель должен оставаться в сети до подтверждения, а получатель — появиться в сети.
- Общий список публичных узлов пока пуст; без bootstrap-узла или общего списка искать собеседника негде.
- Прямое соединение зависит от NAT и firewall. При неудаче используется реле, у которого свои лимиты и доступность.
- История и очередь сообщений хранятся на устройстве **незашифрованными**. `identity.key` лежит в `noBackupFilesDir` и исключён из резервных копий Android, но экспортированный профиль защищён только вами.
- Нет Double Ratchet/Signal, почтового ящика на реле, управления спамом и контактами, а также криптографического аудита.
- Ограничения протокола: 16 000 байт текста, 1 000 исходящих в очереди, 10 000 сообщений истории, 16 bootstrap-узлов, 10 000 записей каталога.
- Уведомления не приходят без разрешения `POST_NOTIFICATIONS`; фоновая работа может быть остановлена системой без исключения из оптимизации батареи.
- Сборка поддерживает только `arm64-v8a` и `x86_64`; APK не содержит `armeabi-v7a`.

## Структура проекта

```
app/                          Android-приложение
  src/main/java/app/svyaz/messenger/
    core/                     модели, настройки, репозиторий узла, уведомления
    service/                  foreground-сервис и автозапуск
    ui/                       экраны Jetpack Compose
  src/test/                   unit-тесты
gocore/                       Go-ядро: libp2p, протокол, профиль, gomobile-мост
  bridge.go                   публичный API для Kotlin
  start.go                    запуск мобильного узла
  node.go                     сетевой протокол
  profile.go                  экспорт и импорт профиля
scripts/build-gocore.sh       сборка app/libs/gocore.aar
gradle/                       version catalog и Gradle wrapper
```

Сетевой код в `gocore/node.go` — дословная копия соответствующей части `main.go` upstream; локальные изменения помечены комментариями `// android:`. Подписываемые JSON-структуры и порядок полей не менялись, чтобы сохранить совместимость с десктопным клиентом.
